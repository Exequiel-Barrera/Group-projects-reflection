Throughout the group projects i have to be part of and worked with , I took on multiple roles, including Git Lead in the Strength project, and contributing to both backend and frontend in projects works such as the Weather Oracle and Merge and Cry Later . These opportunities or experiences working in a team, it  helped me understand how working in a team actually feels in a real development environment, especially when things don’t always go smoothly.

Git Lead for example on the – Strength Project;

In the Strength project, I took on the role of Git Lead, and this was one of the roles where I learned the most.

One of the main issues I faced was around merging branches into main and handling conflicts. There were times where multiple people were working on different branches, and when we tried to merge everything together, we got conflicts, especially in files like package-lock.json.

Another mistake I made early on was not always pulling the latest changes from main before starting work on my own branch. Because of that, when I tried to merge my work later, it created more conflicts than expected and made things harder for the team.

From that experience, I learned how important it is to:

Pull the latest changes before starting work
Keep branches updated regularly
Follow a clear Git workflow as a team

Instead of just fixing things myself, I made sure to work with the team and explain what was happening, so everyone could understand and avoid the same issues. This helped us improve how we worked together.

This role showed me that Git is not just technical, but also about communication and supporting the team. and of course keeping things always up to date 

Backend & Frontend – Weather Oracle Project

In the Weather Oracle project, I worked across both backend and frontend, which helped me understand how both sides connect.

One issue we faced as a group was that the frontend was calling the API, but the requests were failing or returning errors, even though everything looked correct at first.

After working through it together, we realised the problem was a mix of:

API keys not being set correctly in environment variables
Backend not handling errors clearly
Some confusion with how the routes were set up

We didn’t try to solve it individually. Instead, we worked together to debug step by step, checking logs, testing endpoints, and making sure the frontend and backend matched properly.

On the frontend side, I also helped connect the data to the UI and improve how errors were shown, so instead of the app just breaking, it displayed a message when something went wrong.

This project helped me understand:

How frontend and backend depend on each other
How to debug problems as a team
The importance of clear communication
Team Collaboration – “Merge and Cry Later” Project

In the “Merge and Cry Later” project, we built an app that allowed users to search for historical photos of places in New Zealand using an API, and then complete a questionnaire based on the photos.

One challenge we faced was around the search functionality and displaying results from the API. Sometimes the search didn’t return results, or the data wasn’t showing correctly in the app.

As a group, we worked through this by:

Testing the API responses directly
Checking how the data was passed into the frontend
Adjusting how we handled empty or incorrect results

Instead of one person taking over, we shared ideas and worked through it together, which made it easier to find the issue and fix it properly.

This project showed me how important it is to:

Listen to teammates’ ideas
Work together instead of trying to control everything
Support each other when things are not clear
